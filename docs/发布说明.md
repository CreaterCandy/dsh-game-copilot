# 发布说明（维护者）

Release 里放**两个**包，覆盖两类用户：

- `dsh-game-copilot-<版本>-full.zip`（完整包）：代码 + 模型，下载解压跑 `setup.ps1` 即可，不用联网下模型——推荐给大多数用户。
- `dsh-game-copilot-model-small.zip`（模型单包）：只含模型，配 `git clone` 仓库的用户，`setup.ps1` 会自动从 Release 镜像下载并校验。

两者各配一份 SHA256 校验文件。仓库始终保留，供想 clone 的用户使用。

## 1. 首次公开

1. 在 GitHub 新建公共仓库（建议名 `dsh-game-copilot`），把本目录作为首次提交推送。本目录已是独立 git 仓库，不含内部设计文档。
2. 把 `README.md` 里的 `<你的账号>` 换成实际账号名（共 2 处：快速开始的 Releases 链接、折叠块里的克隆地址）。
3. 检查 `LICENSE` 与 `THIRD_PARTY_NOTICES.md` 里的上游链接、素材限制是否符合实际情况。
4. 如果打算商用或不想受上游素材限制，先替换 `plugin/assets/webm/` 的 10 段动画——上游注明禁止商用。

`.gitignore` 已排除虚拟环境、模型、日志、记忆和真实配置；不要手工把它们加进仓库。

## 2. 制作完整包（主分发物）

先准备一份下载好的 faster-whisper small 模型（目录里要有 `model.bin`）。公开仓库本身不含模型，需从已有安装里取，例如 `runtime\models`。

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\pack-release.ps1 -ModelsDir <模型目录> -Version v1.0.0
```

产出：

- `dist\dsh-game-copilot-v1.0.0-full.zip`（约 430MB，解压后是 `dsh-game-copilot\` 整个目录，含 `runtime\models\`）
- `dist\SHA256SUMS-full.txt`（zip 的 SHA256）

脚本用 `git archive HEAD` 导出已提交的代码，自动排除 `.git`、venv、配置、日志等被忽略的东西，再注入模型，所以**打包前先确认代码已提交**。不传 `-Version` 时会取最近的 git tag，没有 tag 则用 `dev`。

`dist/` 是生成物，不需要提交。

## 3. 发 Release

```bash
git tag v1.0.0
git push origin main --tags
```

在 GitHub 新建 Release，关联该 tag，上传**四个**文件：

| 文件 | 给谁用 |
|---|---|
| `dsh-game-copilot-<版本>-full.zip` | 完整包，大多数用户下载解压即用 |
| `SHA256SUMS-full.txt` | 完整包校验 |
| `dsh-game-copilot-model-small.zip` | 模型单包，`git clone` 用户用 |
| `SHA256SUMS.txt` | 模型包校验 |

上传后**必须**把模型包直链和 SHA256 填回 `config/release.json` 并提交推送：

```json
{
  "modelMirrorUrl": "https://github.com/<账号>/<仓库>/releases/download/v1.0.0/dsh-game-copilot-model-small.zip",
  "modelSha256": "<SHA256SUMS.txt 里的那一串>"
}
```

不填这两项，`git clone` 的用户会直接回退 HuggingFace 官方下载（慢），Release 模型包就白传了。完整包用户不受影响——模型已在包里，`setup.ps1` 检测到 `model.bin` 会直接跳过下载。

Release 说明建议写清：版本变化、支持的 Windows / Python 版本、完整包约 430MB 已含模型 / 模型单包约 460MB、非商用限制、端点需要用户自备、以及 SHA256 校验方法。

## 4. 验证

干净目录验证一次完整安装（模拟用户拿到完整包）：

1. 把 `dsh-game-copilot-<版本>-full.zip` 解压到一个全新目录。
2. 里面应有 `setup.ps1`、`plugin\`、`runtime\models\`（含 `model.bin`）。
3. 运行 `powershell -ExecutionPolicy Bypass -File .\setup.ps1`，日志应出现「ASR 模型已就绪，跳过下载」，不触发 464MB 下载。
4. 启动 DSH，设置页出现「桌宠参谋」分区即安装成功。

`git clone` 那条路的验证：克隆仓库 → 确认 `config/release.json` 的直链和 SHA 已填 → 跑 `setup.ps1`，日志应出现「ASR 模型已就绪（镜像）」，不触发 464MB 官方下载。

## 5. 单独重打模型包

只有模型更新、代码没变时，不必重打 430MB 完整包，单独重打模型包即可：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\pack-model.ps1 -ModelsDir <模型目录>
```

产出 `dist\dsh-game-copilot-model-small.zip` + `dist\SHA256SUMS.txt`，按第 3 节上传并更新 `config/release.json`。注意 `SHA256SUMS.txt`（模型包）和 `SHA256SUMS-full.txt`（完整包）是两份不同文件，别混用。

## 6. 后续更新

- **代码更新**：正常 `git commit` / `git push`。完整包用户需要你重打一次完整包并上传新 Release（约 430MB），或在 Release 说明里指明"仅代码变更，可 `git pull` 增量更新"。只改代码时模型单包不用动。
- **模型更新**：按第 5 节单独重打模型包；若代码也变了就两个包都重打。
- **给国内用户提供便利**：可把完整包 zip 放到网盘，README 里给双链接；GitHub Release 仍是权威版本源。

## 7. 隐私检查清单（每次发布前）

- [ ] `git diff` 没有 API Key、真实问答日志、记忆文件
- [ ] 没有本机绝对路径（`C:\Users\...`、`D:\...`）
- [ ] 代码注释里没有内部模型名、倍率、账号信息
- [ ] `plugin/assets/webm` 的禁商用限制仍在 README 与第三方声明里写明
- [ ] `dist\` 没有被误提交（完整包和模型包都只放 Release，不进仓库）
