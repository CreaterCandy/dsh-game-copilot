# 发布说明（维护者）

## 1. 首次公开

1. 在 GitHub 新建公共仓库（建议名 `dsh-game-pet`），把本目录作为首次提交推送。本目录已是独立 git 仓库，只有一条干净历史，不含内部设计文档。
2. 把 `README.md` 里的 `<你的账号>` 换成实际账号名。
3. 检查 `LICENSE` 与 `THIRD_PARTY_NOTICES.md` 里的上游链接、素材限制是否符合实际情况。
4. 如果打算商用或不想受上游素材限制，先替换 `plugin/assets/webm/` 的 10 段动画——上游注明禁止商用。

`.gitignore` 已排除虚拟环境、模型、日志、记忆和真实配置；不要手工把它们加进仓库。

## 2. 制作模型包

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\pack-model.ps1
```

产出：

- `dist\dsh-game-pet-model-small.zip`（解压后是 `runtime\models\`）
- `dist\SHA256SUMS.txt`

`dist/` 是生成物，不需要提交。

## 3. 发 Release

```bash
git tag v1.0.0
git push origin main --tags
```

在 GitHub 新建 Release，关联该 tag，上传上面两个文件。然后把 zip 的**直链**和 SHA256 填回 `config/release.json`：

```json
{
  "modelMirrorUrl": "https://github.com/<账号>/<仓库>/releases/download/v1.0.0/dsh-game-pet-model-small.zip",
  "modelSha256": "<SHA256SUMS.txt 里的那一串>"
}
```

提交并推送。这样用户跑 `setup.ps1` 时会优先走镜像并校验，失败才回退 HuggingFace。

Release 说明建议写清：版本变化、支持的 Windows / Python 版本、模型包约 464MB、非商用限制、端点需要用户自备。

## 4. 验证

干净目录验证一次完整安装：

```bash
git clone <仓库地址> test-install
cd test-install
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

只验证模型镜像链路也可以：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\fetch-model.ps1 -RuntimeDir <临时目录>
```

预期日志出现「SHA256 校验通过」和「ASR 模型已就绪（镜像）」。若镜像地址填错或校验失败，应看到警告并回退官方源，而不是直接崩掉。

## 5. 后续更新

- 代码更新：正常 `git commit` / `git push`，再打新 tag 和 Release。
- 模型包更新：重新跑 `pack-model.ps1`，上传新资产，更新 `config/release.json` 里的 URL 与 SHA256。
- 给国内用户提供便利：可把同一份 zip 放到网盘，并在 README 里给双链接；GitHub Release 仍是权威版本源。

## 6. 隐私检查清单（每次发布前）

- [ ] `git diff` 没有 API Key、真实问答日志、记忆文件
- [ ] 没有本机绝对路径（`C:\Users\...`、`D:\...`）
- [ ] 代码注释里没有内部模型名、倍率、账号信息
- [ ] `plugin/assets/webm` 的禁商用限制仍在 README 与第三方声明里写明
