# 发布说明（维护者）

## 0. 核心策略：大件只传一次，代码版本共用

发布物按"变得快不快"分成两类：

| 类别 | 内容 | 体积 | 上传频率 |
|---|---|---|---|
| **代码包** | `plugin/`、`runtime/*.py`、`setup.ps1`、文档 | **约 8MB** | **每个版本传一次** |
| **模型资产** | faster-whisper small（解压后 `runtime\models\`） | 425.8MB | 只在换模型时传，当前挂在 v1.0.0 |
| **Electron 资产** | 小窗运行时（解压后 `electron\`） | 103.8MB | 只在换 Electron 版本时传，与模型同挂 v1.0.0 |

为什么能共用：**GitHub 的 Release 资产直链是永久的**（`/releases/download/<tag>/<文件名>`），只要不删那个 Release 就不失效。
所以 `config/release.json` 里写死两个大件的直链 + SHA256，`setup.ps1` 首次运行时按直链下载、校验、解压；之后重跑检测到已就绪就跳过。
**两个大件都挂在同一个 Release（v1.0.0）上**，不另开 tag —— 少一个需要记着别删的对象。

结果：日常发版从"重传 537MB"变成"传 8MB"。代价是用户首次安装要联网下 530MB 左右（各一次），这一点在 README 里已明示，同时保留离线完整包给网络差的用户。

## 1. 首次公开（一次性）

1. 在 GitHub 新建公共仓库（建议名 `dsh-game-copilot`），把本目录作为首次提交推送。本目录已是独立 git 仓库，不含内部设计文档。
2. 把 `README.md` 里的 `<你的账号>` 换成实际账号名。
3. 检查 `LICENSE` 与 `THIRD_PARTY_NOTICES.md` 里的上游链接、素材限制是否符合实际情况。
4. 如果打算商用或不想受上游素材限制，先替换 `plugin/assets/webm/` 的 10 段动画——上游注明禁止商用。

`.gitignore` 已排除虚拟环境、模型、日志、记忆和真实配置；不要手工把它们加进仓库。

## 2. 一次性准备两个大件资产

### 2.1 模型资产（约 425.8MB）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\pack-model.ps1 -ModelsDir <下载好的 runtime\models>
```

产出 `dist\dsh-game-copilot-model-small.zip` + `dist\SHA256SUMS.txt`。上传到**一个 Release**（当前指向 `v1.0.0`，已上传，不必重传），再把直链与 SHA256 填进 `config/release.json` 的 `modelMirrorUrl` / `modelSha256`。

### 2.2 Electron 资产（约 103.8MB）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\pack-electron.ps1
```

产出 `dist\dsh-game-copilot-electron-<版本>.zip` + `dist\SHA256SUMS-asset-electron.txt`。
脚本自动按以下顺序找 Electron 发行包（目录里要有 `electron.exe`）：

1. `-ElectronDir` 参数指定的目录；
2. `<仓库>\..\electron-dist\node_modules\electron\dist`（`npm i electron@30.5.1` 到仓库同级目录的产物）；
3. `<仓库>\node_modules\electron\dist`；
4. `%LOCALAPPDATA%\electron`（会清掉其中的 `Cache` 再打包）。

上传到 **v1.0.0 那个已发布的 Release**（模型资产本来就在里面），直接追加资产即可，不用新建 tag：

```
gh release upload v1.0.0 dist\dsh-game-copilot-electron-30.5.1.zip
```

或在网页上打开该 Release → Edit → 拖入 zip。追加后在该 Release 说明顶部补一句：

> 本 Release 除 v1.0.0 程序包外，还挂着**共享大件资产**（`dsh-game-copilot-model-small.zip` / `dsh-game-copilot-electron-30.5.1.zip`），被所有后续代码版本引用。**请勿删除本 Release 或其资产**，删了所有版本的 `setup.ps1` 都装不上。

然后把直链与 SHA256 填进 `config/release.json`：

```json
{
  "modelMirrorUrl": "https://github.com/<账号>/<仓库>/releases/download/v1.0.0/dsh-game-copilot-model-small.zip",
  "modelSha256": "<SHA256SUMS.txt 里的那一串>",
  "electronMirrorUrl": "https://github.com/<账号>/<仓库>/releases/download/v1.0.0/dsh-game-copilot-electron-30.5.1.zip",
  "electronSha256": "<SHA256SUMS-asset-electron.txt 里的那一串>",
  "electronVersion": "30.5.1"
}
```

⚠️ **SHA256 必须填**。不填脚本只跳过校验（打印黄字警告），用户下到半截的 zip 会解压出坏文件，表现成"语音识别不工作 / 小窗起不来"这种极难排查的问题。

⚠️ **两个直链要指向"不会变"的 tag**。本例把两个大件都钉在 v1.0.0 上——它只承载 v1.0.0 的完整包与共享资产，不会随新版本变化；**不要**改成 `latest` 或当前版本号，否则每次发版都得跟着改。

## 3. 日常发版（几十秒，传一个 8MB 文件）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\pack-release.ps1 -NoModels -NoElectron -Version v1.0.2
```

产出：

- `dist\dsh-game-copilot-v1.0.2.zip`（约 8MB，解压后是 `dsh-game-copilot\` 整个目录）
- `dist\SHA256SUMS-code.txt`

脚本用 `git archive HEAD` 直接出 zip（加 `--prefix` 让解压后带 `dsh-game-copilot\` 根目录），自动排除 `.git`、venv、模型、配置、日志等被忽略的东西——**所以打包前必须先 `git commit`，未提交的改动不会进包**。

然后：

```bash
git tag v1.0.2
git push origin main --tags
```

在 GitHub 新建 Release，关联该 tag，只上传上面那两个文件。Release 说明里写清版本变化、支持的 Windows / Python 版本、**首次运行会联网下载约 530MB（模型 + Electron，各只需一次）**、非商用限制、端点需用户自备。

## 4. 可选：离线完整包（大版本偶尔出一次）

给"网络差 / 不想让它联网下大件"的用户。需要模型目录和 Electron 源都在本机：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\pack-release.ps1 -ModelsDir <模型目录> -Version v1.1.0
```

产出 `dist\dsh-game-copilot-v1.1.0-full.zip`（约 540MB）+ `dist\SHA256SUMS-full.txt`。`setup.ps1` 检测到包内已有 `runtime\models\model.bin` 和 `electron\electron.exe` 会直接落地，全程不下载。

**不必每个版本都出**。只在用户明确反馈网络问题时补一个，或者按大版本节奏（如 1.x 的首个版本）出一次。

顺带说明产物命名规则（按实际装了什么推导，不会名不副实）：

| 参数 | 产物名 | 类型 |
|---|---|---|
| 默认 | `dsh-game-copilot-<版本>-full.zip` | 模型 + Electron |
| `-NoElectron` | `...-<版本>-model.zip` | 只模型 |
| `-NoModels` | `...-<版本>-electron.zip` | 只 Electron |
| `-NoModels -NoElectron` | `...-<版本>.zip` | 纯代码（主发包） |

校验值文件名对应 `SHA256SUMS-<full|model|electron|code>.txt`。

## 5. 单独重打某个资产

- **只换模型**：第 2.1 节 → 上传 → 更新 `modelMirrorUrl` / `modelSha256`。代码包不用重打。
- **只换 Electron**：第 2.2 节 → 追加到同一个共享 Release（`gh release upload v1.0.0 <zip>`）→ 更新 `electronMirrorUrl` / `electronSha256` / `electronVersion`。新文件名带版本号（`-30.6.0.zip`），旧文件留着不冲突，老版本仍能装回旧 Electron。
  - 插件端不校验 Electron 版本，只要求 `electron.exe` 存在；实测 20 与 30.5.1 的小窗都能用（拖拽相关的 `setBounds` 写法对两者都成立）。
  - 已装用户不会自动升级 Electron（`setup.ps1` 检测到已有就跳过）。要强制升级得让用户手动删 `%DSH_HOME%\electron`。
- **代码 + 资产都变**：先更新资产和 `release.json`，再按第 3 节发代码包。

## 6. 验证

**代码包这条路**（模拟新用户）：

1. 把 `dsh-game-copilot-<版本>.zip` 解压到一个全新目录，确认里面有 `setup.ps1`、`plugin\`，**没有** `runtime\models\` 和 `electron\`。
2. 运行 `powershell -ExecutionPolicy Bypass -File .\setup.ps1`。
3. 日志应出现「下载 Electron 运行时（约 100MB，只需一次）…」「SHA256 校验通过」「Electron 已装到 …」，以及「ASR 模型已就绪（镜像）」。
4. **重跑一次**，日志应变成「ASR 模型已就绪，跳过下载」和直接找到已有 Electron——证明幂等、不会重复下。
5. 启动 DSH，设置页出现「DSH游戏助理」分区、小窗状态显示「显示中」即安装成功。

**完整包这条路**：解压后运行，日志应出现「ASR 模型已就绪，跳过下载」与「包内自带 Electron」，**不触发**任何大件下载。

**只补装小窗**：`powershell -ExecutionPolicy Bypass -File .\setup.ps1 -OnlyElectron`。已有 Electron 时直接报「已存在，不用重装」；没有则依次尝试"包内 → Release 下载"。

## 7. 隐私检查清单（每次发布前）

- [ ] `git diff` 没有 API Key、真实问答日志、记忆文件
- [ ] 没有本机绝对路径（`C:\Users\...`、`D:\...`）
- [ ] 代码注释里没有内部模型名、倍率、账号信息
- [ ] `plugin/assets/webm` 的禁商用限制仍在 README 与第三方声明里写明
- [ ] `dist\` 没有被误提交（所有包只放 Release，不进仓库）
- [ ] `config/release.json` 的四个字段（模型/Electron 的直链与 SHA256）都是当前有效值
- [ ] 没有删掉 v1.0.0 那个 Release（两个共享大件都在里面），也没删它的 `dsh-game-copilot-model-small.zip` / `dsh-game-copilot-electron-*.zip`

## 8. 国内用户的额外便利

可选：把代码包（8MB）和两个大件 zip 一起放到网盘，README 里给双链接；GitHub Release 仍是权威版本源。
网盘只作镜像，**不要把 `config/release.json` 改成网盘直链**——网盘直链会过期且不支持断点续传。
