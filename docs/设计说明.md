# 设计说明

本文只讲当前实现的结构与取舍，不含开发过程中的内部记录。

## 1. 定位

这是一个**依托 DSH 运行的游戏副驾**：Node 插件提供 HTTP 路由与 UI 插槽，Python 守护负责热键、录音、识别、播报和记忆，Electron 透明窗口负责在游戏上方显示气泡与动画。它不是纯 DSH 插件——ASR、全局热键和置顶小窗都在 DSH 之外。

## 2. 四层职责

| 层 | 代码位置 | 负责 |
|---|---|---|
| Node 插件 | `plugin/` | HTTP 路由（`/state`、`/ask`、`/settings`、`/logs`、`/overlay` 等）、模型路由、能力探针、设置页后端 |
| Python 守护 | `runtime/` | 全局热键、录音、faster-whisper 本地转写、TTS、记忆、问答编排 |
| 显示层 | `plugin/runtime/overlay/` | Electron 透明置顶小窗，气泡五档外观 + 10 段 webm 动画 |
| DSH | 外部 | 插件宿主、HTTP 端口、`settings.section` 插槽、可选的模型通道 |

截图与前台窗口识别由项目自带的 Win32/PowerShell 辅助脚本完成，不经过 DSH 的模型通道。

## 3. 一条按键问答的链路

1. Python 守护捕获热键，播放提示音，录音。
2. `faster-whisper small` 本地转写，不经任何云端服务。
3. Python 调插件的 `POST /ask`，附上问题与当前屏幕截图。
4. 插件按配置的能力档位决定路线：
   - 一步式：图 + 问题一次发给端点；
   - 两步式：图先送给可用的识图端，得到描述后再问回答模型；
   - 盲答：不截图，只答不依赖画面的问题，并在回答里明确说看不到画面。
5. 回答写回 `/state`，显示层冒气泡，Python 侧按 TTS 档位播报。
6. 问答写入本地日志；回答前可按需检索最近几条相关记忆（默认上限 3 条 / 1500 字）。

## 4. 对 DSH 的依赖

| 依赖 | 强度 | 说明 |
|---|---|---|
| `ctx.webServer` | 强 | 所有 HTTP 路由都挂它；Python 守护靠扫描 DSH 端口 + 探 `/state` 找到插件 |
| DSH 自带 LLM 工具库 | 强 | 插件顶层加载它，即使按键问答已经走自定义 OpenAI 兼容端点也绕不开 |
| `ctx.llm` | 弱 | 仅自动开口链路使用；按键问答默认 `askBackend: http`，与 DSH 模型无关 |
| `ctx.slots` | 弱 | 只用于把设置页挂进 DSH，替换成本低 |
| `DSH_HOME` | 弱 | 可回退到 `%USERPROFILE%\.dsh` |
| Electron 可执行文件 | 弱 | 找不到时只丢透明小窗，问答与气泡链路正常 |

`http` 与 `dsh` 两个来源的差别是**凭证管理方式**：前者自己管 baseURL / key，后者走 DSH 登录态与积分。

## 5. 能力探针与降级

设置页填好端点后点「测一下」，插件生成一张随机 4 位数字图发给端点。答对即认定可看图，走一步式；答错则尝试两步式（需另配识图端），都没有就落盲答。盲答档不截图，system prompt 里硬约束不得假装看见画面。

这套判定刻意不依赖任何模型名称白名单——换模型、换端点都靠实测，避免"写着支持其实看不到"。

## 6. 语音

- **录音与识别**：Python + `sounddevice` + `faster-whisper`，模型文件本地缓存，首次安装时下载。
- **播报**：默认 Edge 在线语音；断网落 Windows 系统语音。第三档「本地自然人声」需要用户自行安装微软语音包，设置页探测到真离线音色后才列出，不预置、不分发。
- **正交开关**：桌宠显示与语音问答分别控制；小窗隐藏时语音照念，语音关闭时气泡照显。
- **双念防护**：插件在 `/state` 标记"这条已由 Python 播报"，桥接层据此跳过重复播报。

## 7. 显示与窗口位置

透明小窗用 Electron 无边框窗口 + Pointer Events 拖拽，上报**绝对屏幕坐标**，主进程用 `窗口 = 按下时基准 + (当前光标 - 按下光标)` 计算位置。拖拽与恢复默认位置统一走 `placeWindow()`，以 `setBounds()` 固定宽高。

不单独用 `setPosition()`：在该 Electron / Windows 组合的透明窗口上，每次 `setPosition()` 会让宽高悄悄增长约 1.3px，拖几百帧后窗口膨胀、视觉上"往下掉"。完整证据与验证见 `docs/桌宠小窗拖拽问题排查记录.md`。

小窗位置持久化在用户目录；启动时若与所有显示器都无足够交集，自动回默认右下角。刻意不做全屏感知：真独占全屏下置顶窗本就被盖住，窗口化全屏就是普通窗口，双屏用户拖到副屏即可。

## 8. 日志与隐私

- 主对话日志是 `copilot_log.jsonl`，每条按键问答记录问题、回答、思考链、耗时、路由与错误；另有播报桥日志和两个 stdout 日志。
- 设置页高级区提供只读查看器，默认折叠、点开才加载，大文件只读尾部。
- stdout 日志是 GBK 编码，读取时按 GBK 解码，否则中文乱码。
- 问题、回答、思考链以及纯文本日志里的识别/回答内容默认打码；只有显式 `plain=1` 才出原文，前端再做 HTML 转义防注入。
- 仓库不含真实日志、记忆、配置密钥和虚拟环境，均由 `.gitignore` 排除。

## 9. 部署边界

当前架构是有意保留的混合形态：DSH 管壳与路由，Python 管音频与热键，Electron 管显示。纯插件化会省不掉 Python（faster-whisper 与全局热键没有可靠的 Node 等价物），却会丢掉游戏里最关键的置顶小窗，因此不做。

换机器部署时，代码相对工程目录取路径（`Path(__file__)` / `$PSScriptRoot`），配置走 `%DSH_HOME%`；需要重建的是与本机路径绑定的 `runtime/venv`，模型文件本身机器无关。
